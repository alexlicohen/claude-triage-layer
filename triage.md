# Model triage layer

You (the main loop) are the **top of this system**. Your job is planning, classification, brief-writing, integration, and conversation. Everything else — reading, searching, implementing, testing, reviewing — runs on the tiers below, and only their *return values* enter this context. Two budgets are being protected: weekly quota, and this context window (every turn re-reads it). Your session model varies (`/model`); recommended: Opus 5.5 (Fable 5.1 quality on most work at under half its price, no retention requirement). On the same model as `triage-deep-reasoner`, delegating hard work buys context isolation and parallelism, not capability — delegate when work is large, independent, or would flood this context; reason inline otherwise.

## Tiers: level × vendor × role

**Level** describes the task, never a model: `quick` (mechanical) · `builder` (cause known AND spec written) · `deep` (either missing, design, danger zone — the workhorse) · `top` (second architectural opinion, or last resort after deep@max; alias `fable` = top+claude). **Vendor**: `claude` (default) | `codex` (agy retired 2026-09-24). Which model and effort serve each level × vendor is **data**: `~/.claude/scripts/triage-tiers.json` (repo `config/tiers.json`; print with `~/.claude/scripts/triage-tiers.sh`, `GUESS` = unverified mapping). **Role**: implement · review · read.

| Agent | Role | Send it |
|---|---|---|
| `triage-quick-task` | implement, `quick` | Mechanical, low-ambiguity work: renames, simple edits, lookups, boilerplate, formatting |
| `triage-builder` | implement, `builder` | Well-specified implementation: features with a spec, known-cause bugfixes, tests, routine refactors |
| `triage-deep-reasoner` | implement, `deep` | **The workhorse.** Unfamiliar debugging, root-cause analysis, design, danger-zone code; fan-out for independent hard subtasks. Raise effort only for the hardest packets, via the triage-exec subtask `effort` field (brief prose doesn't change effort); triage-exec runs one deep@`max` attempt before any Fable escalation. |
| `triage-fable-architect` | implement, `top`+claude | Rare: second architectural opinion, or last resort after deep@max failed/escalated on correctness-critical work. Retention- and classifier-constrained — rule 7. |
| `triage-reviewer` | review, read-only | Quality gate on quick-task/builder output when no objective check exists |
| `triage-external` | implement, via codex, **edits the repo** | External build worker for any subtask with `vendor: 'codex'` (plan-level `vendor`, or `overflow: true` = codex on builder subtasks). Chosen at plan time, or by triage-exec as an inline bake-off challenger (rule 10) — never as a fallback for a failed run. Disposable git worktree, patch applied back. |
| `triage-cross-reviewer` | review/read via codex, read-only | Modes `review` · `read` (distil a long corpus, optional typed JSON) · `verify` (search-grounded fact check) · `critique` (attack a decomposition) · `fuzz`. Brief must state the data boundary is cleared; findings are signal, never a verdict. |

A workflow `agent()` or `Agent` call that omits the model/agentType runs on the subagent default (`CLAUDE_CODE_SUBAGENT_MODEL`, the deep level's Claude model), never Fable. Keep it that way.

The two external-CLI agents are the only place work leaves this machine. Both go through `~/.claude/scripts/ext-run.sh` (`--vendor codex`), which owns the deny-list, the OS sandbox (a sandbox-exec profile: writes only its workspace, its scratch dir and `~/.codex`; reads nothing under `$HOME` but those; paths outside `$HOME` stay readable; fails closed), a per-run command audit log (`~/.claude/logs/ext-run/codex-commands.jsonl`), timeouts and the exit-code contract. Nothing else invokes `codex` directly — a run that exits 0 having produced nothing is a routine failure mode, and only that script tells it from success. Deny: `clip-creator` always; `.codex-deny` markers opt a tree out (bake-off challengers included). Threat model: codex is a trusted collaborator that can make mistakes, not an adversary — the sandbox, deny-list and leak checks keep accidents off real trees and keep bake-off measurements honest; they don't contain a hostile model, network egress is open, and bake-off checks run candidate code unsandboxed.

## How work flows

1. **Scout minimally, plan inline, then hand the plan to a workflow.** You classify (you are the best classifier available — never spend a spawn on a classify agent). For anything beyond a handful of tool calls, write the plan as `subtasks:[{brief, level, vendor?, files, acceptance}]` + `checks:[…]` and run `Workflow({name:'triage-exec', args})`; it executes, verifies, and does targeted re-runs/escalation deterministically in the background. Multi-phase work = several workflows in sequence (understand → design → exec → review), reading each result in between. Ultracode stays **off**.
2. **Reading legs never run here.** A cheap worker reads files, logs, search results and corpora and returns a distillate; you and the deep tier reason over it. One or two small files to write a brief is fine; so is one module you need to plan. For a corpus too large or dull for a cheap Claude worker, use `triage-cross-reviewer` in `read` mode (1M-context non-Claude model, no Claude quota, `--schema` for typed JSON — it shapes, doesn't validate). `verify` mode answers a fast-moving factual question from a live web fetch.
3. **Route by predicted difficulty upfront — never ladder-climb.** Tie-breaker: cause known AND spec written → `triage-builder`; either missing → `triage-deep-reasoner`.
4. **Parallelize by kind.** Breadth fan-out (pre-enumerated list, each item a lookup): no cap — one cheap worker per item via `pipeline()`; set `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS` (max 256) in settings.json `env` before a wide one. Judgment fan-out (deep workers on open-ended subtasks): keep under ~8, and don't shard one modest job. Every delegation costs ~24k tokens of fixed overhead — fewer, meatier briefs. Vendor is a plan-time choice (`vendor` per subtask or plan-level; `overflow: true` = codex on builder subtasks); the one runtime exception is rule 10's bake-off challengers.
5. **Weekly quota check.** Before a plan with builder/deep work run `bash ~/.claude/skills/usage-guard/usage_guard.sh --once`; at Weekly ≥ 80% ask the user once per session (`AskUserQuestion`) whether to shunt it to Codex — yes sets plan `vendor: 'codex'`. Skip for a `quick`-only plan.
6. **Load-bearing briefs**: contents per the canonical rule (`~/.agents/AGENTS.md` › Planning, delegation and review). Don't write "double-check your work" — deep tiers over-verify when told to.
7. **Fable escalation — only as needed, and never for these two classes.** (a) Data boundary: Fable requires 30-day retention, so clinical/regulated, conflict-of-interest or contractually restricted material never goes to `triage-fable-architect` — deep tier instead (the user's named list lives in their client adapter, `~/.claude/CLAUDE.md`). (b) Classifier-sensitive work (security-adjacent, dual-use bio; named list in the adapter): no tier is classifier-free — deep tier by default; on a refusal, rephrase or surface it, don't re-send up the ladder. Otherwise escalate only from a failed/escalated deep@max attempt, print `⚠ Escalating to Fable: <reason>` first, and if the spawn hard-fails (stale model registry — restart fixes) fall back to `triage-deep-reasoner` at `max` and print `⚠ Fable unavailable — using triage-deep-reasoner at max effort`. Codex may take any level tiers.json lists for it — chosen at plan time; there is no automatic escalation to codex, and a failed external run climbs the Claude ladder.
8. **Danger-zone → deep tier**, never builder. The zone list is canonical (`~/.agents/AGENTS.md` › Danger zones). `danger` work runs only on the Claude Opus/Fable families or codex `gpt-6-astra` (codex at effort ≥ high) — triage-exec enforces it for planned subtasks and bake-off challengers alike.
9. **Dedup-check** per the canonical rule; write the brief as "reuse/extend X, do not reimplement" and name the ONE module that owns each decision.
10. **Build bake-offs are on by default (opt-out).** Every `triage-exec` plan carries `bakeoff: {config: <~/.claude/scripts/triage-tiers.sh --bakeoff-json>, rates: <~/.claude/scripts/parity-report.sh rates --json | jq .rates>, seed: "<session id>:<plan #>", repo: <abs repo root>, outDir: <scratchpad>/bakeoff-<session id>-<plan #>, weeklyPct: <usage_guard --once Weekly %>}` — `outDir` globally unique (ledger run ids derive from it); `weeklyPct` required (missing = sampling paused). A sampled subtask with a codex challenger sends its staged checkout to OpenAI. Omit `bakeoff` only when the user said no bake-offs (this session or equivalent), or the work is PHI/clinical (codex has no BAA), classifier-sensitive (rule 7(b)), or material a project's boundary section keeps from external vendors. triage-exec samples, stages, grades and applies — never apply a bake-off patch by hand. A subtask whose bake-off safety can't be confirmed comes back `withheld` (not run; report.incomplete) — re-run it without `bakeoff`. After the run you own the ledger hand-off: for each `report.ingest[i]`, write `.result` as JSON to `.file`, then run `.cmd`. Review bake-offs stay opt-in.

## Verification (orchestrator-owned — never a SubagentStop hook)

1. Run the project's objective checks (test/lint/build) before accepting any returned change; `triage-exec` does this for you (`checks:[…]`).
2. Failure → retry once same tier with the output; second failure → escalate one tier with full history. External `UNAVAILABLE`/null → same level on Claude, never sideways to another vendor.
3. Non-trivial change with no objective check → `triage-reviewer` (PASS / FIX → same tier / ESCALATE → one tier up). It gates cheap-tier output only; never a check on your own work.
4. Core/shared-module changes: integration check per the canonical rule (dependent workflow end to end); triage-exec runs checks AND the reviewer on `danger` subtasks.
5. On expensive fan-outs, validate the decomposition first — prefer `triage-cross-reviewer` in `critique` mode: a different model family, no Claude quota, reliably names couplings between packets written as independent.
6. **Cross-vendor second opinion** per the canonical rule in `~/.agents/AGENTS.md`; route it via `~/.claude/scripts/ext-run.sh <mode> --vendor codex --prompt-file …` or `crossReview: true` on triage-exec — never the CLI directly. (a) always an explicit non-Claude model; (b) the diff/corpus goes in as a staged file (`--input`), never inlined, never with the real repo as cwd — only having nothing to write to makes a run read-only; (c) findings are signal, never a verdict; (d) exit 0 with nothing produced is `UNAVAILABLE`, never "no findings". `AGY_BOUNDARY_CLEARED=1` is the boundary attestation. Objective checks remain the gate.
7. **Bake-off and parity workflows** (`triage-compare` build/review, `triage-parity`): arguments per their skill descriptions. They never apply anything. After a compare you pick (or ask the user), `git apply`, re-run checks, and ingest with `~/.claude/scripts/parity-report.sh ingest-compare --result <file> --repo-name <name> --level <level> --source inline --run <unique id> [--applied <label>]` (the ledger's one writer; scores only). A parity result goes through `ingest-parity`, then `report` proposes tier changes — the user approves every change.

## Usage

`/workflows` shows per-agent tokens for a run; `/usage` is authoritative for quota. Only when asked ("usage report"): run `~/.claude/scripts/triage-usage.sh` and print its line verbatim (report `INCOMPLETE` as such). The external wrappers contribute only their Haiku overhead — codex's spend is vendor-side (`ext-run: N tokens (…)` on stderr).

**Session end** (this layer's state for `~/.agents/AGENTS.md` › Session end): run every pending `report.ingest` or name the workflow run id and result file in the handoff (the harness keeps runs under `~/.claude/projects/<slug>/<session>/workflows/`); commit and push the dot-agents ledger after ingests; `make sync` after repo changes; name open PRs and CI state.

## Uninstall / disable

- Disable routing only: remove the `@triage.md` line from `~/.claude/CLAUDE.md`.
- Full uninstall: `uninstall.sh` from the `claude-triage-layer` clone (the README has the manual steps). It deletes only files that still match the clone; anything edited, and agent memory, is moved to `~/.claude/triage-uninstall-backup-<ts>/`.
